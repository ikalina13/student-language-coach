# Salita Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Offline Windows vocabulary app (Electron, local JSON storage, PDF report) plus a static download site, built and released free via GitHub Actions.

**Architecture:** Pure CommonJS modules in `app/core/` (storage, auth, progress, content logic, report HTML) are unit-tested with `node --test`. Electron main process wires them to IPC; a preload exposes `window.salita`. Renderer is plain HTML/CSS/ES modules with a hash router. `site/` is a separate static site.

**Tech Stack:** Node 20+, Electron (latest stable), electron-builder (NSIS), `node:test`, plain HTML/CSS/JS.

**Spec:** `docs/superpowers/specs/2026-11-19-salita-design.md`

## Global Constraints

- Windows 10/11 64-bit; NSIS per-user one-click; artifact name `Salita-Setup.exe`.
- Data dir: Electron `app.getPath('userData')` → `%APPDATA%\Salita\`; `users.json`, `progress/<username>.json`.
- No SQL, no network in the app; fonts/assets bundled.
- `contextIsolation: true`, `nodeIntegration: false`.
- Usernames 3–20 chars `[A-Za-z0-9_]`, case-insensitive unique, stored lowercase; password ≥ 4 chars; scrypt + 16-byte random salt.
- Grades 4–10; suggested level: 4–5 beginner, 6–8 intermediate, 9–10 advanced.
- Categories (ids): `school, family, food, animals, places, feelings, actions, common`. Levels: `beginner, intermediate, advanced`.
- Themes: mode `light|dark`; accent `blue|red|green|purple|orange`; default light + blue.
- Quiz = 10 questions, 4 options, distractors from same category.
- Content: ~30 words per category×level, 3 stories/level with 3 questions each, 20 sentences/level.
- Visual direction: calm, deliberate, no gradient/glass/emoji-heavy "AI" look.

## Review Focus

1. Username differing only in case ("Ana" vs "ana") → rejected as taken; login works with any case. (Task 2 test)
2. Corrupt or hand-edited JSON file → app starts, file reset to empty, original kept as `.bak`. (Task 1 test)
3. Username with path characters (`../x`) → rejected before any file path is built. (Task 2 test)
4. Quiz where several words share the same Filipino meaning → 4 distinct option texts, exactly one correct. (Task 4 test)
5. Dictionary search with mixed case / extra spaces / Filipino word → finds match; empty query returns all (filtered). (Task 4 test)

### Task 4: Content logic

**Files:** Create `app/shared/content.mjs` (ES module so the renderer can import it directly; tests use `import()`), `tests/content.test.js`

**Interfaces — Produces (from `app/shared/content.mjs`):**
- `dailyWord(words, date: Date) → word` — sort by id, seeded shuffle (mulberry32 seed 2026), index = floor((localMidnight(date) − 2026-01-01)/86400000) mod length (non-negative).
- `buildQuiz(words, {category, level}, rng = Math.random) → [{wordId, prompt: 'What does "<word>" mean?', options: [string×4], answer: index}]` (10 or fewer if pool smaller).
- `searchWords(words, {query, category, level}) → words` — case-insensitive, trimmed, matches `word` or `filipino` substring; sorted by word.
- `CATEGORIES`, `LEVELS` arrays of `{id, label}`.

- [ ] Step 1: Tests: dailyWord same for same day, differs next day, stable across times in a day; quiz has 10 questions, 4 distinct options each, `options[answer]` equals the word's filipino, no option repeats when two words share a meaning; search `"  HaPpy "` finds happy, `"masaya"` finds happy, empty query + category filter returns only that category.
- [ ] Step 2: FAIL → implement → PASS. Commit `feat: daily word, quiz, search`.
